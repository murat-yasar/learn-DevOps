# Docker Compose
> Docker Compose is a tool that allows you to define, configure, and run multiple Docker containers together using a single YAML file.
> While a Dockerfile describes how to build an image, Docker Compose describes how different containers (services) work together.

For example, a typical TYPO3 application needs:
- PHP / Web server
- MariaDB database
- Redis (optional)
- Mailpit for testing emails (optional)

Instead of starting and configuring each container manually, Docker Compose manages everything for you.

## 1. Example: Docker Compose Example
Project structure:
```
my-project/
├── Dockerfile
├── compose.yaml
├── index.php
└── .dockerignore
```

compose.yaml:
```yaml
services:

  web:
    build: .
    container_name: my-php-app
    ports:
      - "8080:80"
    volumes:
      - .:/var/www/html
    depends_on:
      - database

  database:
    image: mariadb:11
    container_name: my-database
    environment:
      MARIADB_ROOT_PASSWORD: secret
      MARIADB_DATABASE: myapp
      MARIADB_USER: myuser
      MARIADB_PASSWORD: mypassword
    volumes:
      - database_data:/var/lib/mysql
    ports:
      - "3306:3306"

volumes:
  database_data:
```

## 2. Understanding compose.yaml

### A. services
```yaml
services:
  web:
    ...
  database:
    ...
```
services defines the containers that make up your application.

Here we have two services:
- web: PHP application.
- database: MariaDB database.

Each service normally runs in its own container.

### B. build vs image
There are two important options:

- build
> Docker Compose looks for a Dockerfile in the current directory and builds an image.
```yaml
web:
  build: .
```

- image
> Docker Compose downloads and uses an existing image from a registry (Docker Hub by default).
```yaml
database:
  image: mariadb:11
```

### C. ports
> This maps ports between your computer and the container.
```yaml
ports:
  - "8080:80"
```
Access the application using: http://localhost:8080

### D. volumes
> It connects your local project directory to a directory inside the container.
```yaml
volumes:
  - .:/var/www/html
```
This is called a bind mount.

### E. environment
> Environment variables configure the database when the container initializes.
```yaml
environment:
  MARIADB_ROOT_PASSWORD: secret
  MARIADB_DATABASE: myapp
  MARIADB_USER: myuser
  MARIADB_PASSWORD: mypassword
```
For real projects, avoid committing passwords directly into Git. Use an .env file or secrets management.

### F. depends_on
> Tells Compose to start a service before another service. For reliable startup, use a health check and condition: service_healthy.
```yaml
depends_on:
  - database
```
In this case: start database service before the web service.

## 3. Essential Docker Compose commands
| Command	| Purpose |
| ------- | ------- |
| docker compose up -d	| Start all services in background |
| docker compose down | Stop and remove containers and network |
| docker compose down -v | Also remove named volumes (data loss!) |
| docker compose ps |	List services and their status |
| docker compose logs |	Display logs |
| docker compose logs -f web | Follow web service logs |
| docker compose build | Build or rebuild images |
| docker compose restart |	Restart services |
| docker compose exec web bash |	Open a shell inside web container |
| docker compose pull |	Download newer images |

```yaml
# Start everything
docker compose up -d

# Check containers
docker compose ps

# View logs
docker compose logs -f

# Enter PHP container
docker compose exec web bash

# Stop everything
docker compose down
```

## 4. Networking
> By default, Compose creates a network for your application. Services can communicate using their service names as hostnames.

Ex: PHP application connects to MariaDB using
```php
$pdo = new PDO(
    'mysql:host=database;dbname=myapp',
    'myuser',
    'mypassword'
);
```
